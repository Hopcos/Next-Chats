## 高风险问题（按风险排序）

### H1. ApiErrorMiddleware 状态码映射错误：`NOT_FOUND` 落到 403 而非 404
`src/NextChats.Api/Middleware/ApiErrorMiddleware.cs:39`
```csharp
context.Response.StatusCode = code is "FORBIDDEN" or "NOT_FOUND" ? 403 : code == "LLM_UNAVAILABLE" ? 503 : 500;
```
`KeyNotFoundException` → code=`"NOT_FOUND"`，但被 403 分支吞掉，返回 **403** 而不是 **404**。语义错误：资源不存在与无权限应区分。
**建议**：`NOT_FOUND` 映射 404，`FORBIDDEN` 映射 403：
```csharp
context.Response.StatusCode = code switch
{
    "FORBIDDEN" => 403,
    "NOT_FOUND" => 404,
    "LLM_UNAVAILABLE" => 503,
    _ => 500,
};
```

### H2. 工具结果成败判定依赖魔法前缀 `❌`（脆弱契约）
`AgentLoopEngine.cs:224` 与 `:385/:403`
```csharp
!toolResult.StartsWith("❌", StringComparison.Ordinal)   // 判定是否成功
return $"❌ {result.ErrorCode ?? "TOOL_ERROR"}: {lastError}"; // 失败消息拼接
```
- 耦合点：错误文案前缀 `❌` 与文本内容绑定，且**任何外部工具只要返回以 `❌` 开头的内容即被误判为失败**；
- 未来若把错误前缀本地化（zh/en 不同符号）会破坏该判定。
**建议**：失败标志结构化——`McpToolResult`/`ToolExecResult` 已有 `Success` 布尔，AgentLoop 直接以 `result.Success` 判定并把 `❌` 前缀改为常量（如 `ErrorMarker`），或在 ToolResult 事件里显式传 success。

## 中低风险问题

### M1. AgentLoopEngine 死代码
`AgentLoopEngine.cs:126-131`
```csharp
if (interrupted || outcome.Interrupted)
{
    interrupted = true;
    if (!interrupted) _ = interrupted;  // 恒 false，死代码
    _ = trace;                          // 无意义
    break;
}
```
上一行刚把 `interrupted` 置 true，`if (!interrupted)` 永假；`_ = trace` 无副作用。应清理为 `if (interrupted || outcome.Interrupted) { interrupted = true; break; }`。

### M2. LlmRouter.SelectClientAsync 空 catch 吞异常
`LlmRouter.cs:75-91`：`catch { }` 吞掉**所有**异常再走故障转移。若 `CreateClient` 未来可能抛 `OperationCanceledException`（eg. 构造期网络探测），取消会被误吞并继续尝试 fallback。建议将取消排除：
```csharp
catch (OperationCanceledException) { throw; }
catch (Exception) { /* 故障转移 */ }
```

### M3. SSE 流末尾 `SafeAwait(producer)` 在取消时缺少兜底上限
`AgentLoopEngine.cs:113-116`：客户端断连（`RequestAborted` 取消）触发 `finally { await SafeAwait(producer); }`，依赖 producer 对 `ct` 的响应。若底层 LLM 客户端不响应取消，枚举器会挂住（会话/连接泄漏）。建议给 `SafeAwait` 加超时（如 `Task.WhenAny(producer, Task.Delay(5s, CancellationToken.None))`），超时后不再等待。

### M4. 无请求上下文路径固定 en（已记录权衡，建议注释留痕）
`LlmRouter.PingAsync` / `ContextManager` / `SkillExecutionEngine` / `McpDriver` 兜底均 `Texts.Get(..., "en")`。行为正确（默认英文），但这些调用方无 `lang` 上下文，一旦未来需要管理端按语言展示会漏译。建议：
- 在相关方法 XML 注释中显式标注「固定 en，无请求上下文」；
- 或提供重载入口接收 lang（管理端 Ping 已通过 Controller `Err("LLM_UNREACHABLE", error)` 二次本地化，属于可接受的现状）。

## 改进建议（低优先级）

1. `ApiControllerBase.Lang` 每次访问重新解析请求头（环境相对廉价）；如需极致可缓存到一个私有字段，但现值可接受。
2. `Texts.Get` 未知 code 返回 code 本身便于发现问题——建议为字典缺失注册一个 `Serilog` 告警日志（DEBUG 级，避免噪声），并可在测试中 `foreach (ref in Texts 使用点) Assert(Texts.Has(code))` 固化码表完整性。
3. `ApiControllerBase.LanguageOf` 与 `ApiErrorMiddleware.LanguageOf` 重复实现，可提取到 `Core.Localization` 的共享 helper（`LangHeader.Read(HttpContext)`），避免未来语义漂移。
4. `LlmUnavailableException` 默认消息固定 en 已知权衡；若要求 zh 场景也本地化，可在 AgentLoop 捕获后统一用 `Texts.Get("LLM_UNAVAILABLE", lang)` 覆盖（现已在事件层做了，✓）。
5. 枚举字符串序列化（`JsonStringEnumConverter`）为全局配置：会让所有枚举字段（Role/ApprovalStatus/Transport/Kind 等）统一输出字符串——已与前端（`fromDto` 的 'Assistant'/'User' 断言、status 筛选）对齐；但属**全局行为变更**，若有第三方客户端期望数字，需在接口文档中注明。

## 正面确认（本次变更质量亮点）

- **lang 贯穿链路干净**：HTTP `X-Lang` → `ApiControllerBase.Lang` → `ChatStreamRequest.Lang` → `ChatOrchestrator` → `AgentRunRequest.Lang` → `AgentLoopEngine` → `LlmRouter.SelectClientAsync(lang)` → `MockLlmClient(lang)` —— Core 无 ASP.NET 依赖，lang 仅 string，设计清晰。
- **单一字典**：所有用户可见文案收敛到 `Texts.cs`（en/zh 双列、`{0}` 插值、未知 code 回退 code），controller 层经 `Err(code, args)` 全量替换，符合「代码中不硬编码界面文案」的目标；残留中文均为日志/注释（合规）。
- **SSE 审批链路**：移除缓冲式 `ErrorLocalizationMiddleware`（该中间件会把 SSE 流整体缓冲导致审批事件不可达的死锁），审批事件实时到达、decide → Approved → 工具执行全链路验证通过。
- **异常本地化兜底完整**：`ApiErrorMiddleware` 500/403/503 位码、`HasStarted` 保护 SSE 已写头场景；controller 层 IActionResult 直接携带本地化 message。
- **数据库种子英文化**：`DbSeeder` 角色/管理员/Prompt/Skill/Mock 供应商全英文，默认英文体验成立；`Entities.Title` 默认空 + 旧数据「新会话」兼容判断健壮。
